# Workspace Manifest Implementation Plan

**Goal:** The workspace manifests are ready for the walking skeleton's code.

**Architecture:** Every manifest and lock change except the console script lands in this one plan,
so plans 02-05, which may run in parallel worktrees, never edit `pyproject.toml` files or `uv.lock`
at the same time. Plan 06 adds the console script after them (it depends on 05). Sibling
members are wired through a root `[tool.uv.sources]` table, keeping the CLAUDE.md rule that members
carry no `[tool.*]` tables.

**Tech Stack:** uv 0.13.6 workspaces, `uv_build`, pytest, `importlib.metadata`.

**Content authority:** spec §1 premise 5, §2.

## Order of work

### Task 1 — Raise the interpreter floor to 3.14.10

**Files:**
- Modify `.python-version` — `3.14` becomes `3.14.10` (today `.python-version:1`).
- Modify `packages/ijob-core/pyproject.toml`, `packages/ijob-ai/pyproject.toml`,
  `packages/ijob-sources/pyproject.toml`, `packages/ijob-app/pyproject.toml` — line 9,
  `requires-python = ">=3.14"` becomes `">=3.14.10"`.
- Modify `uv.lock` — regenerate with `uv lock`; its `requires-python` follows.
- Test each member's `test_package.py` (four files listed above).

**Change:** every member, the lock and the interpreter pin agree on 3.14.10, the interpreter whose
`urllib.robotparser` the spec's probes verified (spec §1 premise 5). The python guideline keeps
`.python-version` equal to the floor (`SKILL.md:50`).

**Proof:** written first, seen failing, then passing —
- `test_package_requires_python_floor` (one per member) — the installed distribution's
  `Requires-Python` metadata (`importlib.metadata.metadata(<dist>)["Requires-Python"]`) is
  `>=3.14.10`. The installed metadata carries the specifier verbatim: today's install of `ijob-core`
  reads `Requires-Python: >=3.14` (`.venv/lib/python3.14/site-packages/ijob_core-0.1.0.dist-info/METADATA:7`,
  found during review).

**Done when:** `uv run --locked pytest packages/*/tests/*/test_package.py` passes and the five-command
gate in CLAUDE.md is green. Commit `build: raise the python floor to 3.14.10`.

### Task 2 — Declare the runtime dependencies

**Files:**
- Modify `pyproject.toml` (root) — add `[tool.uv.sources]` with `ijob-core = { workspace = true }`
  and `ijob-sources = { workspace = true }`.
- Modify `packages/ijob-sources/pyproject.toml` — `dependencies = ["httpx>=0.28.1,<0.29", "ijob-core"]`.
- Modify `packages/ijob-app/pyproject.toml` — `dependencies = ["typer>=0.27.3,<0.28", "ijob-core",
  "ijob-sources"]`.
- Modify `uv.lock` — regenerate with `uv lock`.
- Test `packages/ijob-sources/tests/ijob_sources_tests/test_package.py`,
  `packages/ijob-app/tests/ijob_app_tests/test_package.py`.

**Change:** `ijob-sources` can import `httpx` and `ijob_core`; `ijob-app` can import `typer`,
`ijob_core` and `ijob_sources`. `ijob-core` and `ijob-ai` keep `dependencies = []`. Runtime
dependencies take a compatible range and the lock pins the exact version (spec §2); the dev group
stays pinned with `==`. The console script is not declared here: its target module arrives in plan
06, which adds it.

**Proof:** written first, seen failing, then passing —
- `test_runtime_dependencies_declared` in `ijob_sources_tests/test_package.py` — the distribution's
  `Requires-Dist` names `httpx` and `ijob-core`.
- `test_runtime_dependencies_declared` in `ijob_app_tests/test_package.py` — the distribution's
  `Requires-Dist` names `typer`, `ijob-core` and `ijob-sources`.

**Done when:** `uv sync --locked --all-groups --all-packages` succeeds, the two tests pass and the
gate is green. Commit `build: declare walking-skeleton runtime dependencies`.

## Risks

- **Most risky step: the lock regeneration.** A stale lock fails every later `--locked` gate step,
  so `uv lock` must run after each manifest edit and `uv.lock` must be committed in the same commit.
- A `[tool.uv.sources]` entry is required for each sibling a member names; a missing one makes
  `uv lock` fail (python guideline `workspace.md:214-221`), which is the immediate signal.
- The CI workflow is not changed: it runs the same gate, which runs on the interpreter
  `.python-version` names (python guideline `SKILL.md:48`).
- Not done: no member gets a `[tool.*]` table, and no runtime dependency is pinned with `==`.

- The five-command gate in CLAUDE.md is green.
- `uv run --locked python -c "import httpx, typer, ijob_core, ijob_sources"` exits 0.
