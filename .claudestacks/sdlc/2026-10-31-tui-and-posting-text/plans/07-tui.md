# TUI Implementation Plan

**Goal:** `ijob tui` opens a Textual app that covers every interaction milestone ijob-v1/03 names, built on `ijob_app.service`.

**Architecture:**
- New package `ijob_app.tui` (spec §7). Its `__init__.py` holds only a docstring, a sorted `__all__` and the re-export of `IjobApp` (`references/init-export-only.md`). There is one module per screen: `app.py` (the main screen and the app), `note.py`, `sources.py` and `cv.py`.
- `IjobApp(service: Service, config: Path | None)` never opens a store itself. `ijob tui` opens the service with `open_service` (plan 05) and calls `IjobApp(...).run()` on the same thread, so the store stays on the loop's thread (spec §5, `store.py:270`).
- Every service call that awaits (`refresh`, `detail`, `label`, `add_source`, `add_url`) runs in an async `@work` worker on the app loop (`_work_decorator.py:74,110-115`; spec §7 probe).
  - Each kind of call has its own worker group, exclusive within that group only: `refresh`, `detail`, `label` and `sources`. Textual's `exclusive` cancels every worker in the same group (`_work_decorator.py:82-84,95`; `worker_manager.py:75-76`), so moving the cursor never cancels a running refresh.
  - Failures surface through `App.notify` (`app.py:4621`).
- Filter reading is shared with the CLI. `_FilterFlags` and `_read_filters` (`cli.py:403-460`) move to `ijob_app.config` as the public `FilterFlags`, with field defaults of empty tuples and `None`, and `read_filters`.
  - `config` also gains `flags_from_spec(spec: FilterSpec) -> FilterFlags`, which renders a spec back to the text a user types: country codes, remote values, `since` as `<n>d` for whole days or `<n>h` otherwise, companies, `AMOUNT:CURRENCY:PERIOD`, and `require_salary`.
  - It also gains `spec_from_flags(base: FilterSpec, flags: FilterFlags) -> FilterSpec`, which sets every flag-able field from `flags`, so an empty value means no filter. The role patterns stay from `base`.
- Tests mirror `src` (guideline `test-mandate.md`): `packages/ijob-app/tests/ijob_app_tests/tui/` with `__init__.py`, `test_app.py`, `test_note.py`, `test_sources.py` and `test_cv.py`. They take the shared fixtures from `ijob_app_tests/conftest.py` (plan 05): a temporary XDG environ, a ticking clock and a `MockTransport` client factory. They build the service with `open_service`, drive the app with `async with app.run_test() as pilot`, and run the coroutine with `asyncio.run` (spec §9). Before asserting, they always `await app.workers.wait_for_complete()` (`worker_manager.py:172`) and `pilot.pause()`.

**Tech Stack:** Python 3.14, Textual 8.2.8 (`DataTable`, `Markdown`, `Input`, `Checkbox`, `ModalScreen`, `Footer`), Typer, pytest.

## Risks

- **Async test timing** is the most likely source of flaky tests. Always await `app.workers.wait_for_complete()` and `pilot.pause()` before asserting, as the spec §7 probe does.
- **Store thread.** A service call in a thread worker would raise SQLite's same-thread error (spec §7 probe). No `thread=True` worker is used anywhere in `ijob_app.tui`, and the Proof grep holds this.
- **Lock growth.** `rich`, `markdown-it-py` and `pygments` are already locked (`uv.lock:296,395,420`). New entries include Textual, `platformdirs`, `mdit-py-plugins`, and the `linkify-it-py` that Textual's `markdown-it-py[linkify]` requirement pulls in (wheel METADATA:27), along with their own dependencies. Review the `uv lock` diff before committing.
- `spec_from_flags`, `flags_from_spec` and the per-group workers are recorded in the amended spec §7.
- Not done: a file browser, fallbacks for terminals without emoji, and mouse-only flows.
