"Verified" means a live request returned the stated status and data. Anything that was not fetched live is marked **UNVERIFIED**.

## Priority-1 notes

### JapanDev (japan-dev.com)

**How it works:** Nuxt 3 SSR. Search uses InstantSearch with a **Meilisearch** backend (`instantMeiliSearch('https://meili.japan-dev.com', <public search key>)`, index `Job_production`). The SSR HTML embeds the first page of results inside `<script type="application/json" id="__NUXT_DATA__">`. That payload is devalue-encoded: a flat array in which objects reference other entries by index, and `["ShallowReactive", n]` wrappers have to be unwrapped. Path: `data["algolia-state-jobs:<path>"]["Job_production"]["results"][0]`, with keys `hits`, `nbHits`, `hitsPerPage` (60), `nbPages`, `facets`.

**Requests that worked (all 200):**
- `GET https://japan-dev.com/jobs`: 562 KB, 60 hits, nbHits=282, facets job_type_names={Engineering:249, Product:16, Other:12, Design:4, Business Dev:1}. Total in `data["jobs-count"].jobs_count` = 282.
- `GET https://japan-dev.com/ai-jobs-in-japan`: SSR is pre-filtered, nbHits=23.
- `GET https://japan-dev.com/cdn/sitemaps/sitemap.xml` (linked from `/sitemap.xml`): 1,449 URLs, 290 of them `/jobs/<company>/<slug>`. No lastmod on job URLs.
- `GET https://japan-dev.com/jobs/alpaca/alpaca-senior-software-engineer---new-markets-japan-jlpt-n1-fluent-swq1og`: includes `application/ld+json` JobPosting with title, description (HTML), datePosted, validThrough, employmentType, hiringOrganization{name,sameAs}, jobLocation.address, jobLocationType (TELECOMMUTE), applicantLocationRequirements, occupationalCategory.

**Hit fields (from SSR):** `id, title, company_name, company{name,slug,logo_url,is_verified}, location, salary_min, salary_max, has_salary_data, salary_tags[], skills[{name,system_name,skill_type}], skill_names[], job_type_names[], remote_level (remote_level_none|partial|full_japan|full_worldwide|around_office), seniority_level (junior|mid_level|senior|new_grad|unknown), japanese_level_enum, english_level_enum, candidate_location, sponsors_visas, employment_type, contract_type, is_internship, published_at, created_at, updated_at, job_post_date, slug, application_url, application_email, company_tag_names[], company_is_startup`.
Detail URL is `https://japan-dev.com/jobs/{company.slug}/{slug}`.

**Pagination limitation:** `?page=2` and `?Job_production[page]=2` do not change the SSR output, because paging happens client-side through Meilisearch. You can get full coverage in one of these ways:
1. **Recommended:** fetch the sitemap (1 request), diff it against known slugs, then fetch the JSON-LD only for new job pages (about 290 requests at 1 rps, roughly 5 minutes the first time and incremental after that).
2. Fetch the SSR of several engineering landing pages (each gives up to 60 hits): `/engineering-jobs-in-japan`, `/ai-jobs-in-japan`, `/web-developer-jobs-in-japan`, `/sre-devops-jobs-in-japan`, `/ml-data-science-jobs-in-japan`, `/engineering-manager-jobs-in-japan`, `/remote-jobs-in-japan`, `/jobs-in-japan-salary-over-10m`. The default sort is newest first (sort_at), so for an incremental crawler the newest 60 on `/jobs` plus `/engineering-jobs-in-japan` are probably enough.
3. **UNVERIFIED / not tested:** `POST https://meili.japan-dev.com/indexes/Job_production/search` with `Authorization: Bearer <public search key from the JS bundle>` and a body like `{"q":"backend","filter":"job_type_names = \"Engineering\"","limit":100,"offset":0}`. This is the frontend's own search API and would be the simplest approach (one request, full filters). It was **not called**: the call was blocked by this session's safety policy as possible circumvention. The user should decide whether using a public search key embedded in the frontend is acceptable. Ideally ask JapanDev first.

### Let's Get Rusty Jobs (jobs.letsgetrusty.com)

**What it is:** the Rust-only job board run by the "Let's Get Rusty" YouTube/education brand. `https://letsgetrusty.com/jobs` redirects to `https://jobs.letsgetrusty.com/`. It is a static Astro v5 site and the record IDs (`rec...`) suggest Airtable as the data store. 202 live jobs, all Rust (SWE) roles across blockchain, AI, infra and embedded.

**Requests that worked (all 200):**
- `GET https://jobs.letsgetrusty.com/` and `GET https://jobs.letsgetrusty.com/?page=2` (pages 1 to 21, 10 jobs each). Each page embeds `<script type="application/ld+json">` with `{"@type":"ItemList","itemListElement":[{"item":{"@type":"JobPosting","title","description"(truncated ~150 chars),"datePosted":"2026-10-28","hiringOrganization":{"name","logo"},"jobLocation":{"address":{"addressCountry":"Remote"|"Germany"...}},"employmentType":"FULL_TIME","url":"https://jobs.letsgetrusty.com?job=rec3bDClKwtB7VEIV"}}]}`. The card HTML also shows On-site/Remote/Hybrid, location and level (e.g. "Mid-level").
- `GET https://jobs.letsgetrusty.com/?job=rec3bDClKwtB7VEIV`: a full JobPosting JSON-LD with the complete markdown description. The apply URL is in the button `onclick="window.open('https://dex-labs.breezy.hr/p/.../apply')"`.
- `GET https://jobs.letsgetrusty.com/sitemap-index.xml`, then `/sitemap-0.xml`: 202 `?job=` URLs.

**Adapter:** walk `?page=1..N` until a page has no new `?job=` IDs (21 requests), parse the ItemList JSON-LD, and optionally fetch details for new IDs only. Filter by level, location or remote client-side, because the server-side filter params (`query=`, `level=`, `industry=`, `location=`, `type=`) are robots-disallowed. **Do not use the default `python-requests` UA, which is explicitly disallowed.** No salary field was observed.

### JobStreet (SEEK): blocked

- **robots.txt** (my, sg, id and ph are identical): `User-agent: *` gets `Disallow: /api/jobsearch/`, `Disallow: /graphql`, `Disallow: */job/` and `Disallow: *?`, with `Allow: *?keywords` and `Allow: *?advertiserid`. `anthropic-ai`, `GPTBot` and `CCBot` are additionally blocked from `/companies` and `*/job/`.
- **ToS** (my.jobstreet.com/terms): cl. 7(d) says "You may not use data mining, robots, screen scraping, or similar automated data gathering". Cl. 9(b) says automated access is not allowed without an approved interface such as an API. Cl. 9(d) says SEEK uses technical measures to detect automated access and that "Circumventing these measures is prohibited".
- **Live check:** `GET https://my.jobstreet.com/software-engineer-jobs` (and the same path on sg, id and ph, and seek.com.au) returned **403 with a Cloudflare managed JS challenge**. No data came back.
- **JSON API (UNVERIFIED, not called because robots disallows it):** the SPA calls `GET https://{cc}.jobstreet.com/api/jobsearch/v5/search?siteKey=MY-Main&where=Kuala+Lumpur&keywords=software+engineer&classification=6281&subclassification=6287&daterange=7&salaryrange=...&salarytype=monthly&page=1&pageSize=32&sortmode=ListedDate&locale=en-MY`. Response: `{totalCount, data:[{id, title, companyName, advertiser{description}, locations[{label}], salaryLabel, listingDate, teaser, bulletPoints, classifications[{classification,subclassification}], workTypes, workArrangements}], ...}`. Classification codes come from third-party scraper docs (Apify listings).
- **Recommendation:** do not crawl JobStreet or SEEK. The only compliant integration is to deep-link ("open search in browser"), e.g. `https://my.jobstreet.com/software-engineer-jobs?keywords=...`. SEEK says it has no public job-search API for job seekers. A partner API may exist for advertisers only.

## Blockers and caveats
- **Cloudflare 403 for non-browser clients:** JobStreet (all country sites), SEEK AU, TokyoDev, NodeFlair, Glints, CareerCross. I did not try to get past any of these. Changing the UA to look like a browser was considered and rejected as circumvention.
- **Robots exclusions:** GaijinPot Jobs disallows everything. JobStreet/SEEK disallow `/api/jobsearch/`. LetsGetRusty disallows its filter params, `/api/` and the `python-requests` UA.
- **JapanDev full pagination** needs either per-job detail fetches (from the sitemap) or the internal Meilisearch endpoint (UNVERIFIED, needs a user decision).
- **Best "API-grade" sources found:** MyCareersFuture (public JSON) and Kalibrr (frontend JSON, unauthenticated).
